## Releases This Week

### Claude Code

**5 versions in-window** (2.1.328 → 2.1.332). Two substantive feature drops: **2.1.330 (11/20)** — Enterprise Admin Console sign-in + easel charts + 30-day /loop + /rm tightening + Enterprise Admin Console self-hosted-runner orchestrator metrics; **2.1.332 (11/25)** — Skills from MCP servers (beta) + `PreSkillShellCommand` hook event. **2.1.331 (11/23)** extends Code Mode to cloud providers. **2.1.329 (11/19)** is near-pure stability (10 improvements, 91 fixes, 1 regression). **2.1.328 (11/19)** continues Code Mode polish and self-hosted runner work. Full per-version changelog at [code.claude.com/docs/en/changelog](https://code.claude.com/docs/en/changelog).

**Skills over MCP (agent-team lens: HIGH when MCP-server maintainers adopt)**
- **v2.1.332 (11/25)** — Added **skills from MCP servers (beta)** as `server:skill` entries in the `/` menu; other skills keep their names. **HEADLINE #1.** Companion to the 11/24 Anthropic announcement that Skills over MCP is in public beta across Claude and Claude Code, and that Tasks + Elicitation extensions are generally available for Pro/Max/Ultra. Server-authored skills live and version next to the server's tools — no reinstall when the skill changes. Discovery: whichever MCP server opts in advertises skills, and Claude loads each only when needed to keep context tight.
- **v2.1.332 (11/25)** — Added **`PreSkillShellCommand` hook event** so a managed hook can refuse a skill's or command's inline shell commands at load. Older versions open a dialog at start when a settings file names this hook. **Direct fit for Strandworks**: add this hook wherever a project's managed settings already refuse shell patterns, so a newly-loaded MCP-sourced skill with a surprise inline `rm`/`curl | sh` gets the same filter.
- **v2.1.332 (11/25)** — `computer-use` became a reserved skill name on Macs with computer use on; a Strandworks-authored skill/command of that name would stop loading with a startup notice to rename. Likely low exposure — Strandworks has no `computer-use` named skill — but worth a `rg "computer-use" ~/.claude/skills ~/PROJECTS/_ops/**/skills` sweep.

**Code Mode expansion (agent-team lens: MEDIUM on cloud, N/A on scouts)**
- **v2.1.331 (11/23)** — Added **Code Mode support in terminal sessions on Amazon Bedrock, Google Cloud Agent Platform, Microsoft Foundry, and Claude Platform on AWS**. **HEADLINE #2.** Still excludes: `claude -p`, Agent SDK, VS Code panel, Desktop, Remote Control, gateways, Enterprise Admin Console sign-in with Amazon Bedrock Mantle or Microsoft Foundry, HIPAA, ZDR, Claude for Government. Strandworks runs direct-to-Anthropic-API without cloud-provider routing; the expansion is orthogonal to the daily workflow but closes the "cloud deployments can't use Code Mode" gap for the day MedSim-Game or MedCapture lands a cloud-deployed inference customer.
- **v2.1.329 (11/19)** — **Code Mode now runs with OpenTelemetry events/metrics on**; each tool call sends events; tracing still disables it. Direct fit for Strandworks only if a scout starts exporting OpenTelemetry.
- **v2.1.328 (11/19)** — Code Mode's `UserPromptSubmit` hook no longer runs on scripts' output (even when managed); use a `PostToolUse` hook with `updatedToolOutput` to redact instead. **Direct fit for Strandworks** if any `UserPromptSubmit` hook today greps script output — move the check to `PostToolUse` on `REPL`.
- Multiple Code Mode stability fixes across 2.1.328-332: large-script-output path for cut-off text (2.1.331), prompt-cache preservation in auto mode (2.1.328), retrying failed edits with closest-match hint (2.1.328), terminal freeze after subagent script makes thousands of tool calls (2.1.329 improvement, 2.1.330 further).

**Recurring tasks + /loop headroom (agent-team lens: MEDIUM-HIGH for scout fleet)**
- **v2.1.330 (11/20)** — **Recurring scheduled tasks and `/loop` wakeups now run up to 30 days** (up from 7) while the session keeps running; the session says when the schedule ends. Pre-release scheduled tasks still cap at 7 days. **HEADLINE #3.** Direct fit for Strandworks: `_ops/claude-scout`, `_ops/tech-scout`, Telegram daemon, Shadow worker all run under `/loop`-equivalent schedules; a single long-running session can now span a month without re-scheduling. No code change required — the ceiling is lifted silently for sessions on 2.1.330+.
- **v2.1.330 (11/20)** — "Exit and stop tasks" now ends the session's scheduled tasks so they don't fire on resume (unless exited while Claude is still responding). Behavior change worth noting for the Shadow worker's exit path.
- **v2.1.330 (11/20)** — Saved scheduled tasks in new signed-in sessions: most saved by earlier versions need scheduling again (own session's `--resume` still runs them). **Direct fit for Strandworks**: the first startup after the 2.1.330 upgrade may wipe Shadow worker schedules; re-add them from the deployment manifest, don't trust auto-carry.

**Terminal charts (agent-team lens: LOW-MEDIUM; one-shot ergonomic win)**
- **v2.1.330 (11/20)** — Added **`easel`**: built-in mod that draws charts when asked and under MCP metrics results. Pro/Max/Team/Enterprise, macOS/Linux. **HEADLINE #4.** Direct fit for Strandworks: `swd report` summaries with numeric outputs, Supabase SQL that returns a time series, Linear burndowns via the Linear MCP, and ADVERTISING metrics can all surface inline terminal charts without a browser round-trip. Turn off in `/config` if the auto-chart under MCP tools becomes noise in scout transcripts.

**`rm` safety tightening (defense-in-depth lens: MEDIUM for headless scouts)**
- **v2.1.330 (11/20)** — **More `rm` commands aimed at root, home, top-level, or working folder now ask for approval; where nobody can answer, refused.** **HEADLINE #5.** Direct fit for Strandworks: any `claude -p` scout that today contains an `rm -rf <var>` pattern with a variable that could expand to `~`, `/`, or the working dir is now refused automatically. Confirm by running a scout in dry-run mode and watching for the refusal notice. No deliberate change required; defense-in-depth lands at the upgrade.
- **v2.1.329 (11/19)** — Auto mode now refuses Claude's call to stop `/loop` (the next wake-up still fires). Direct fit for Strandworks `/loop` scouts that occasionally self-cancel in error.

**Enterprise Admin Console sign-in (platform lens: strategic only)**
