**Code Mode (agent-team lens: HIGH on interactive refactors, N/A on scouts)**
- **v2.1.323 (11/12)** — Added **Code Mode (experimental)**, in which Claude writes JavaScript to call its tools in one step instead of asking for each tool call separately. See [code.claude.com/docs/en/code-mode](https://code.claude.com/docs/en/code-mode). Opt in by setting `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1` in the shell or in `~/.claude/settings.json`. **HEADLINE #1.** Requirements: **interactive `claude` session in a terminal**, Opus 5.5 / Sonnet 5.5 / Haiku 5.5 / Fable 5.2 model, direct Anthropic API (not Bedrock/Vertex/Foundry/GCP-Anthropic-managed), subscription or Console account, not HIPAA and not ZDR, not `--restricted`, native build, Git for Windows on Windows. **Does not work with `claude -p`, the Agent SDK, the VS Code panel, the Desktop app, cloud sessions, Remote Control, Claude in Chrome, or computer use.** Permission semantics: each generated tool call goes through `deny` and `ask` rules and `PreToolUse` hooks under its usual tool name (e.g. `Bash`); auto-mode's classifier reviews the **code** (not each call), so run-time-computed values don't get classifier review — keep deny rules or `PreToolUse` hooks for calls you must control. `PreToolUse` on `REPL` can read the raw JavaScript from `tool_input.code` before it runs. Long-running code runs ten minutes in foreground; two hours in auto / `bypassPermissions` background mode. Resume requires Code Mode to still be on (`claude --continue` with the env var set). To block for an organization, set `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=0` in [managed settings](https://code.claude.com/docs/en/managed-settings.md).
- **v2.1.326 (11/16)** — Added **Code Mode support with agent teams**; teammates run in Code Mode in the default [in-process display mode](https://code.claude.com/docs/en/agent-teams.md#choose-a-display-mode) and start without it in split panes.

**MCP + token-hygiene (security-adjacent lens: MEDIUM-HIGH)**
- **v2.1.327 (11/17)** — Added `claude mcp add-json <name> -` to **read the server's JSON from stdin, so tokens can stay off the command line**; not available inside a Claude Code session. **HEADLINE #2.** Shell history / `ps` / background-telemetry collectors no longer see bearer tokens, API keys, or refresh tokens pasted into `claude mcp add-json`.
- **v2.1.323 (11/12)** — Added **a start-up warning for Bash allow rules with a `*` in a variable's value**, such as `Bash(PORT=* npm run dev)`. Direct fit for Strandworks: audit any project `settings.json` for allow rules of this shape — the wildcard-in-variable pattern is a known bypass surface (the 2.1.319 Bash env-prefix fix, Headline #2 last scout, closed an adjacent hole).
- **v2.1.326 (11/16)** — Added a start-up warning when an `--allowedTools`, `--disallowedTools` or `--tools` value has an entry that doesn't look like a complete rule.

**Code Mode permission semantics (auto-mode + hooks)**
- **v2.1.323 (11/12)** — `PreToolUse` hooks that allow or block shell commands must now check each part of a command as [Bash rules do](https://code.claude.com/docs/en/permissions.md#compound-commands) — in Code Mode a `git push` in a folder named `app` can reach your hook as `cd 'app' && git push`. **Direct fit for Strandworks** if a hook greps a Bash command for `git push` or similar without parsing shell compound syntax.
- **v2.1.323 (11/12)** — `UserPromptSubmit` hooks on `command`, `http`, or `mcp_tool` events now also run on code output when Code Mode code runs in the background. To let output through, change the hook so that it doesn't block when `source` in its input is `poll_event`.

**Plugin platform (developer-productivity lens)**

- **v2.1.323 (11/12)** — Added type checking of a plugin's TypeScript hooks module to `claude plugin validate`; each finding is a warning, and `--strict` fails on it. Same applicability caveat.
- **v2.1.325 (11/13)** — [VSCode] Added a Console sign-in that creates no API key.
